API 设计  ### 7.0 认证方式设计（v3.0 Magic Link + 邮箱密码双轨 · V3.1 Google OAuth）  v3.0 支持三种认证方式，**并存不互斥**，用户可任选：  #### 7.0.1 方案总览  | 方式 | 默认 | 复杂度 | 体验 | |---|---|---|---| | **Magic Link** | ✅ | v2.0 已实现 | 无密码、点邮件链接登录 | | **邮箱密码**（双轨）| ✅ | 1-2 天 | 传统体验，首次设置后免邮件 | | **Google OAuth** | ❌ | 1-2 天（V3.1）| 一键授权，适合 Gmail 用户 |  **原则**：不强制用户设置密码，首次 Magic Link 登录后可「绑定密码」（账号设置里点一下就设上）。  #### 7.0.2 Magic Link 流程（默认，v2.0 已实现）  ``` 用户访问 /auth   ↓ 输入邮箱 → POST /api/auth/magic-link   ↓ 后端生成 32 字节 URL-safe 随机 token   ↓ 写入 magic_links 表（expires_at = now + 15min）   ↓ 发邮件：点击下方按钮登录   ↓ 用户点链接（带 ?token=xxx）   ↓ GET /api/auth/verify?token=xxx   ↓ 后端校验 token 未过期 + 未使用 → 创建 session → Set-Cookie   ↓ 跳转回原页面（已登录） ```  **安全机制**：  - Token：32 字节随机（256 位），URL-safe base64  - 过期：15 分钟  - 一次性使用：标记 `used_at`  - Session：httpOnly + secure + sameSite=strict cookie，30 天有效  **防垃圾**：  - 同一邮箱 5 分钟内只能申请 1 次  - 同一 IP 1 分钟内只能申请 1 次  - 24h 内同一邮箱最多 5 次  #### 7.0.3 邮箱密码流程（v3.0 双轨新增）  ##### 7.0.3.1 注册流程  ``` 用户访问 /auth → 选「邮箱 + 密码注册」   ↓ 输邮箱 + 密码（8位以上、数字字母）   ↓ POST /api/auth/register { email, password }   ↓ 后端：     1. 校验邮箱格式 + 密码强度     2. 检查邮箱未注册     3. bcrypt hash 密码（cost=12）     4. 创建 user 记录（email_verified=false）     5. 发验证邮件（Magic Link，purpose=email_verify）   ↓ 前端：「请查收邮件验证邮箱」   ↓ 用户点验证链接 → 邮箱验证 → 登录态生效   ↓ 跳回原页面 ```  **为什么不立即登录**：邮箱未验证前不允许下单/付费（防垃圾注册 + 邮箱资产）。  **例外**：首单免费单张与 Yes/No 免费抽**不需要邮箱验证**（v0.8 Review
